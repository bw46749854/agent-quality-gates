# 設計判断の記録

あとから「なぜこうなっているのか」と問われそうな判断を、1件につき1ファイルで残します。
ファイル名は `0001-短い名前.md` の形で、ひな形は [`0000-template.md`](0000-template.md) です。

## 残す判断

- コンポーネントの追加・分割・統合
- 依存の向きの変更、新しい依存の追加
- 抽象（インターフェース・層）を足す、またはあえて足さない判断
- 技術の選定（言語・フレームワーク・保存先・外部サービス）
- 品質ゲートを外す、またはしきい値を緩める判断
- 原則どおりにしなかった箇所と、その理由

## 残さなくてよい判断

- コードを読めば分かること
- すぐに元へ戻せて、ほかに影響しないこと

決めたことを覆すときは、古い記録を書き換えずに、新しい記録を作って古いほうの「状態」を「置き換え済み」にします。
